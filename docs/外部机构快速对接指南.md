# 外部机构：用 Skill 快速对接卡开放 API

面向**外部合作机构 / 商户研发**。在支持 Agent Skills 的 AI 编码工具（如 Cursor）中安装本技能后，用自然语言即可完成：**选方案 → 出对接流程 → 沙箱跑通 → 生成可落地代码**。

开放文档入口：[opendocs.kun.global](https://opendocs.kun.global/) · [API 对接指南（无 SDK）](https://opendocs.kun.global/docs/api-integration/api-integration-without-sdk)

---

## 1. 你能得到什么

| 阶段 | 产出 |
|------|------|
| 选型 | 商务卡 / 消费卡 / Webhook，以及预付卡 vs 共享账户 |
| 流程 | 有序接口步骤（含查单、通知） |
| 跑通 | 沙箱已签名调用命令或可执行示例 |
| 落地 | 含状态判断、异常分类、幂等与查单补偿的实现代码（**多语言**） |

技能 ID：`kun-card-integration`（仓库：`yeezus-skills`）· **完整能力**：[CAPABILITY.md](../skills/kun-card-integration/CAPABILITY.md)

**覆盖**：从零接入（商务卡/消费卡/Webhook）+ **旧 VCC 迁移**（YOP → 新 RSA；无双轨期）。  
**语言**：与 **yop-demo** 对齐 — Python / Java / Java-Web / Node.js / TypeScript / Go / PHP / .NET。详见 `多语言对齐.md`。

---

## 2. 对接前准备（机构侧）

向开放平台拿到（沙箱优先）：

| 项 | 用途 |
|----|------|
| App-Key | 请求头 |
| Customer-No | 请求头并参与签名 |
| RSA 商户私钥（PEM 文件） | 本地签名；**只提供文件路径，勿粘贴到聊天** |
| secretKey | 业务报文机构密钥（≠ RSA 私钥） |
| （可选）cardProductCode | 已开通卡产品；没有可先调产品列表接口 |

环境：

| 环境 | 网关 |
|------|------|
| 沙箱 | `https://sandbox.kun.global` |
| 生产 | `https://openapi.kun.global` |

本地建议：跑 `kun_client.py` 联调时需 Python ≥ 3.10；**业务代码语言不限**，按你们工程栈（可与 yop-demo 一致）在对话中指定。

## 3. 安装 Skill（约 1 分钟）

拿到 `yeezus-skills` 仓库后：

**个人安装（本机所有项目可用）：**

```bash
cd /path/to/yeezus-skills
mkdir -p ~/.agents/skills
ln -sfn "$(pwd)/skills/kun-card-integration" ~/.agents/skills/kun-card-integration
test -f ~/.agents/skills/kun-card-integration/SKILL.md && echo "安装成功"
```

**仅当前业务项目：**

```bash
cd /path/to/your-project
mkdir -p .agents/skills
ln -sfn /path/to/yeezus-skills/skills/kun-card-integration .agents/skills/kun-card-integration
```

> 软链必须指向 `skills/kun-card-integration/` 目录（含 `SKILL.md` 的那一层），不要链到仓库根目录。

**验证：** 新开一轮 Agent 对话，发送下面任一句话，Agent 应加载卡对接技能并按场景追问/给方案：

- 「我要对接合规卡开放 API，商务卡预付虚拟卡」
- 「帮我对接消费卡 KYC 开卡」

若无反应：确认软链存在，并重启 / 新开 Agent 会话。

## 4. 怎么用对话「快速对接」（推荐话术）

一次说清 **场景 + 环境 + 语言**，可走快速通道，少轮澄清。  
语言请从 yop-demo 矩阵任选：`Python` / `Java` / `Java-Web` / `Node.js` / `TypeScript` / `Go` / `PHP` / `.NET`。

### 4.1 商务卡 · 预付虚拟卡（最短闭环）

```text
请用 kun-card-integration 帮我对接合规卡开放 API。
场景：商务卡、预付模式、虚拟卡。
环境：沙箱。语言：TypeScript。   # 可改为 Python / Java / Node.js / Go / PHP / .NET 等
请直接给出：对接步骤、示例 JSON、可执行的 kun_client 命令（联调），
以及可落地的开卡代码（含 SUCCESS/FAIL/PENDING 判态、超时只查单、异常分类）。
我已有 App-Key / Customer-No / 私钥文件路径 / secretKey；cardProductCode 若未知请先教我拉产品列表。
```

### 4.2 商务卡 · 共享账户

```text
商务卡共享账户模式：先建共享户再充值再开卡。
沙箱 + Go。请给出完整流程、字段注意点、可落地代码骨架（含账户充提 PROCESSING 状态处理）。
```

### 4.3 消费卡 · KYC + 虚拟卡

```text
消费卡：先 KYC 再开虚拟卡。沙箱 + Java。
请说明 KYC Level1 必填、通过后再开卡的顺序，并生成可落地代码（含 KYC 状态与开卡 PENDING 查单）。
```

### 4.4 授权 Webhook

```text
需要接交易授权 Webhook：如何验签、如何返回 A/D、如何幂等。语言：Node.js。
请基于 skill 示例给出可落地的接收服务代码，并说明超时与重复通知怎么处理。
```

### 4.5 旧 VCC 迁移

```text
请用 kun-card-integration 做旧 VCC 迁移。我用 open.kun.global 的 /rest/v1.0/vcc/* 与 yop-demo。
语言：Java。请给：鉴权改造（YOP→新 RSA）、接口对照、查单/Webhook 必改项、切换清单（无双轨期）。
```

### 4.6 排障

```text
沙箱开卡返回 PENDING / 或签名失败 / 或收不到 webhook。
环境：沙箱。接口：…。错误码/原文：（粘贴脱敏后的报错）。
请按技能里的状态与异常规范给出排查步骤，不要猜生产根因。
```

**安全提醒：** 聊天里用 `YOUR_*` 占位；私钥只说**本机路径**（如 `./keys/merchant_private.pem`），不要粘贴私钥内容、完整卡号、证件号。

## 5. 推荐 15 分钟路径（商务卡预付）

```text
① 安装 skill，新开对话，发送 §4.1 话术
② 按 Agent 输出配置公钥到开放平台（若尚未配置）
③ cd skills/kun-card-integration/scripts
   pip install -r requirements.txt
   python kun_client.py gen-key --out-dir ./keys   # 或使用平台已分配密钥
④ 用 Agent 给出的 call 命令调 cardBins → 拿 cardProductCode
⑤ 添加持卡人 → openCard → 若 PENDING 则 openCardQuery
⑥ 把 examples/commercial_prepaid_flow.py 拷进你们工程，改配置与落库
⑦ 需要控额时再接授权 Webhook（examples/webhook_auth_handler.py）
```

成功标准：

- 沙箱：`openCardStatus` 或查询结果为 `SUCCESS`，拿到 `cardId`
- 代码：本地能区分成功 / 失败 / 处理中；超时**只查单不重开**

## 6. Agent 应交付的检查清单（验收）

机构方可按此验收 AI 输出是否合格：

- [ ] 方案：商务卡或消费卡（及账户模式）说清楚了  
- [ ] 流程：接口顺序正确，含查单  
- [ ] 示例：JSON 可直接改占位符试跑  
- [ ] 命令或示例可在沙箱执行  
- [ ] 代码含 `requestNo`、平台 `code` 校验、业务状态分支  
- [ ] 说明了 PENDING / 超时未知怎么处理  
- [ ] 未要求你把私钥贴进聊天  
- [ ] 生产调用有二次确认提示  

不满足「可落地」几项时，可追问：

```text
请按技能「交付标准」补齐：状态判断、异常分类、查单补偿和上生产清单，不要只给 curl 示例。
```

## 8. 常见问题

**Q：不会写签名怎么办？**  
用技能内 `scripts/kun_client.py`，或让 Agent 按鉴权文档生成你们语言的签名代码。

**Q：开卡一直 PENDING？**  
属正常中间态。用开卡时的 `requestNo` 作 `originalRequestNo` 调状态查询；不要换新单重开。详见状态判断文档。

**Q：可以跳过 KYC 直接开消费卡吗？**  
不可以。消费卡须 KYC 通过后再开卡；商务卡走「添加持卡人」，不要混用。

**Q：生产怎么切？**  
网关改为 `https://openapi.kun.global`，使用生产密钥与 IP 白名单；首次真实写操作须在对话中明确确认生产风险。
