# 旧 VCC → 新开放 API 迁移总览

> **范围**：商务卡旧 VCC（`/rest/v1.0/vcc/*`）。消费卡 / caas 迁移另册。  
> **无双轨期**：不承诺旧新网关长期并存；策略为 **沙箱改完 → 生产切新 → 停用旧客户端**。  
> **语言**：与 yop-demo 对齐，见 [`../产品能力/多语言对齐.md`](../产品能力/多语言对齐.md)。

---

## 1. 何时走迁移

客户提到：`旧VCC` / `yeevcc` / `open.kun.global` / `/rest/v1.0/vcc` / `yop-demo` / `YOP 加密签名` → 先读本目录，再按 [`接口对照表.md`](接口对照表.md) 改代码。

从零对接新 API（无旧代码）→ 直接走 [`../产品能力/最小跑通.md`](../产品能力/最小跑通.md)，不必读迁移。

---

## 2. 范式切换

| 维度 | 旧（YOP / open.kun） | 新（opendocs） |
|------|---------------------|----------------|
| 文档 | https://open.kun.global/docs/apis/ | https://opendocs.kun.global/ |
| 鉴权 | YOP v3 RSA（对照 **yop-demo** 各语言） | RSA SHA256withRSA 头签 |
| 密钥 | YOP appKey / 私钥等 | `App-Key` + 商户 RSA 私钥 + Body `secretKey` |
| 调用 | 大量 GET + Query | 以 POST + JSON Body 为主 |
| 终态 | 易误判 HTTP 200 | 平台 `code` + 业务状态 + 查单 |
| Webhook | 旧 path / HMAC v1（yop-demo） | 新类型与验签（见 Webhook 对接） |

旧算法细节：对照本地 **yop-demo**（`yopV3Signer`、响应验签、AES 工具、Webhook HMAC），按客户语言打开对应 `*-demo`。

---

## 3. 迁移步骤（无双轨）

```text
① 鉴权改为新 RSA 头签（废弃 YOP 请求链路）
② 按 mapping 替换 path；GET→POST；补 requestNo + secretKey
③ 资金写操作接查单（含旧无、新有的账户查单；卡充值/转出查询拆分）
④ Webhook 配置与验签全量切新
⑤ 沙箱冒烟
⑥ 生产切换清单勾选后发布（一次性切新；回滚=回滚应用版本）
```

已对齐：`user-cards` → `POST /rest/v2.0/api/common/userCards`；`card-remark` → `POST /rest/v2.0/api/common/updateCardRemark`（见对照表与 OpenAPI 片段）。
