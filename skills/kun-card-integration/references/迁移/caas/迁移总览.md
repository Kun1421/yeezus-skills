# CAAS 迁移总览

> **本目录只覆盖旧 CAAS**（消费卡，`/rest/v1.0/caas/*` → `/rest/v2.0/caas/*`）。  
> **不要用于旧 VCC。** 商务卡 `/rest/v1.0/vcc/*` 走 [`../vcc/迁移总览.md`](../vcc/迁移总览.md)，禁止套用 `vcc/mapping.yaml` 或 VCC 能力差异（`customerId` 商户语义、`cardBinId`、开卡 `accountMode` 1/2 等）。

---

## 1. 何时走这里

客户旧 path 是 `/rest/v1.0/caas/*`，或明确说消费卡 / 旧 CAAS 迁移 → 读本目录。

旧 path 是 `/rest/v1.0/vcc/*`、yeevcc、YOP 商务卡 → 离开本目录，改读 VCC。

从零对接新消费卡（无旧代码）→ [`../../产品能力/消费卡/消费卡对接.md`](../../产品能力/消费卡/消费卡对接.md)，不必做迁移对照。

---

## 2. 和 VCC 的边界

| | VCC 迁移 | CAAS 迁移 |
|--|----------|-----------|
| 旧前缀 | `/rest/v1.0/vcc/` | `/rest/v1.0/caas/` |
| 产品 | 商务卡 | 消费卡（KYC、实体卡、PIN、预售、包装地址） |
| 对照数据 | `../vcc/mapping.yaml` | **尚未单列**。`lookup_mapping.py` 不查本目录 |
| 新接口说明 | 商务卡对接 | [`消费卡对接.md`](../../产品能力/消费卡/消费卡对接.md) |

新侧头签（`App-Key` / `Api-Version` / `Customer-No` / `Timestamp` / `Sign`，Body `secretKey` + `requestNo`）与 VCC 新侧相同，见 [`../vcc/鉴权迁移.md`](../vcc/鉴权迁移.md) 的「新侧」。那一页的旧 path 对照仍然只属于 VCC。

---

## 3. 当前可确认的 path 规律

公开文档里，多数消费卡接口只改版本段：`/rest/v1.0/caas/<后缀>` → `/rest/v2.0/caas/<后缀>`。后缀例：`card/apply-card`、`customer/kyc-submit`、`file/recon-file-download`。以 [`api-index.yaml`](../../产品能力/api-index.yaml) 里带 `legacy_doc` 的条目为准。

这不是字段级对照。未写进本目录的差异不要用 VCC 的能力差异填。缺对照时说明「CAAS 字段对照未单列」，并只给出新 path 与消费卡对接文档，不要编一组 VCC 式字段映射。

---

## 4. 还没写进本目录的内容

- 旧 CAAS → 新 CAAS 的 `mapping.yaml` / 接口对照表  
- 同能力字段差异（身份、金额、查单键）  
- 无对等接口的缺口清单  

补这些材料时只放在 `references/迁移/caas/`，不要写回 `vcc/`。
