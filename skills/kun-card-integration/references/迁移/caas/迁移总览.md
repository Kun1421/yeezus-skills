# CAAS 迁移总览

> **本目录只覆盖旧 CAAS**（消费卡，`/rest/v1.0/caas/*`）。  
> **不要用于旧 VCC。** 商务卡 `/rest/v1.0/vcc/*` 走 [`../vcc/迁移总览.md`](../vcc/迁移总览.md)。不要把 VCC 的 `customerId`、`cardBinId`、开卡 `accountMode` 差异套到 CAAS。  
> 对照机器可读：[`mapping.yaml`](mapping.yaml)。路径清单：[`接口对照表.md`](接口对照表.md)。

---

## 1. 怎么迁

绝大多数接口 **只改路径，参数与旧版相同**：把 `/rest/v1.0/caas/` 换成 `/rest/v2.0/caas/`，请求体和响应体原样。

例外只有三类：

1. **开卡**：旧 `apply-card` 还能用。建议改到开卡 V2，并用 V2 新增的按请求号查状态。  
2. **Sumsub**：V2 新增的共享 KYC 流程，旧 CAAS 没有。不替换现有 `kyc-submit` / KYC SDK。  
3. **表里写明「原来没有」的能力**：账户充值/转出查单、卡转出及查单、批量开卡/销卡。不替换现有充值、销卡接口。

新侧头签与 VCC 新侧相同，见 [`../vcc/鉴权迁移.md`](../vcc/鉴权迁移.md) 的「新侧」。那一页的旧 path 仍然只属于 VCC。

---

## 2. 开卡

| | 路径 | 怎么用 |
|--|------|--------|
| 旧开卡，仍可用 | `POST /rest/v2.0/caas/card/apply-card` | 参数与 `/rest/v1.0/caas/card/apply-card` 相同 |
| 旧开卡的查单，仍可用 | `POST /rest/v2.0/caas/card/query-apply-card-status` | 只查仍走 `apply-card` 的单，字段不变 |
| **建议** 开卡 V2 | `POST /rest/v2.0/api/common/openCard` | 与旧 `apply-card` 隔离。不要拿旧开卡的请求体原样提交 |
| **V2 新增** 按请求号查状态 | `POST /rest/v2.0/api/common/openCardQuery` | `originalRequestNo` = 这笔 `openCard` 的 `requestNo` |

留在旧开卡：版本段改成 v2.0，查单继续用 `query-apply-card-status`。  
改到 V2：新开的卡走 `openCard`，查单只用 `openCardQuery`。同一笔 `requestNo` 不要两套开卡各打一次。

## 3. Sumsub（V2 新增）

旧 CAAS 没有这条流程。已有的 KYC 报送和 KYC SDK 仍然只改路径、参数不变。

机构要复用持卡人在 Sumsub 已完成的 KYC 时：

```text
① POST /rest/v2.0/caas/customer/kyc-sumsub-shareToken
② 同步响应只表示受理，不是审核终态
③ 终态走既有 KYC 结果通知 /rest/v2.0/caas/customer/kyc-notify
```

请求字段：`requestNo`、`secretKey`、`customerId`、`ip`、`shareToken`、`kycLevel`。  
`kycLevel` 取值：`KYC_Level_1`、`KYC_Level_1_AML`、`KYC_Level_2`、`KYC_Level_2_AML`。  
带 `_AML` 的等级按现有 KYC 规则传 `amlResult`（`Approve` / `Reject`）。  
`shareToken` 一次性使用，不要打进日志明文。

同步结果看 `code` 和 `data.status`：

| `code` | `data.status` | 含义 |
|--------|---------------|------|
| `0000` | `ACCEPTED` | 已受理，等 `kyc-notify` |
| `0000` | `SUCCESS` | 沿用已通过的案件，响应带 `caseNo` |
| 非 `0000` | — | 未受理。等级非法、token 已用过、已有处理中的案件时，换条件或等通知，不要用同一个 `shareToken` 重放 |

## 4. 旧侧没有的接口

这些不替换现有 CAAS 接口，是新能力：

| 能力 | 新 path |
|------|---------|
| 账户充值状态查询 | `POST /rest/v2.0/api/common/accountTransferInQuery` |
| 账户转出状态查询 | `POST /rest/v2.0/api/common/accountTransferOutQuery` |
| 卡转出 | `POST /rest/v2.0/api/cardManagement/cardTransferOut` |
| 卡转出状态查询 | `POST /rest/v2.0/api/cardManagement/cardTransferOutStatusQuery` |
| 批量开卡 / 任务查询 | `POST /rest/v2.0/api/common/batchOpenCard`、`batchOpenCardTask` |
| 批量销卡 / 任务查询 | `POST /rest/v2.0/api/common/batchCancelCard`、`batchCancelCardTask` |

卡充值、卡充值查单、充值明细、单笔销卡仍走原来的 CAAS 路径（只改版本段）。

---

## 5. 不要做的事

表后半把销卡、激活、卡信息、冻结、限额、MCC、充值、余额、充值明细又对到了一套 `/rest/v2.0/api/...`。  
**默认迁移不要改这些字段，也不要改走那套路径。** 继续用 [`接口对照表.md`](接口对照表.md) 里的 `/rest/v2.0/caas/...`。只有开卡按第 2 节建议切 V2。
