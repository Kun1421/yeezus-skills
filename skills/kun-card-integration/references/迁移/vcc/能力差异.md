# VCC 能力差异

> **只覆盖旧 VCC**（`/rest/v1.0/vcc/*`）。不要套到旧 CAAS。CAAS 见 [`../caas/迁移总览.md`](../caas/迁移总览.md)。  
> path 以本目录 [`接口对照表.md`](接口对照表.md) / [`mapping.yaml`](mapping.yaml) 为准。  
> 本文只写调用侧必须改的语义和字段。  
> 图例：`mapped` 可替换 · `partial` 有新接口但不等价 · `gap` 新侧无对等 · `new_only` 仅新侧。

---

## 1. 跨接口必改

| 维度 | 旧 VCC | 新开放 API |
|------|--------|------------|
| 路径 | `/rest/v1.0/vcc/...` | 商务 `/rest/v2.0/api/...`；账户/交易/文件/配置多为 `/rest/v2.0/caas/...` |
| HTTP | 文档侧 GET 与 POST 混用 | 几乎全部 POST + JSON Body |
| 鉴权 | YOP | Header：`App-Key` / `Api-Version` / `Customer-No` / `Timestamp` / `Sign`；Body：`secretKey` + 唯一 `requestNo` |
| 成功 | 旧响应包装 | HTTP 恒 200。看 `code`，`0000` 成功。结构 `{requestNo,code,message,data}` |
| `customerId` | 商户 ID | 商务卡接口 = **持卡人 ID**。机构/商户放 Header `Customer-No` |
| 卡定位 | `cardId` 或 `cardNumber` | 只认 `cardId` |
| 产品 | `cardBinId`（数字） | `cardProductCode`（字符串）。开卡前先调 `cardBins` |
| 开卡账户模式 | `sharedAccountNo`，或整数 `cardType` / `isShare` | `accountMode`：`1` 预充值 / `2` 共享。共享时再传 `accountNo` |
| 卡形态 | 整数 `cardType` 兼表普通/共享 | `cardType`：`V` 虚拟 / `P` 实体。共享语义只在 `accountMode` |
| 异步查单 | `taskId` / `orderId` | `originalRequestNo` = 原请求的 `requestNo` |
| 金额 | 十进制金额（元） | 卡资金字段多为整数。按产品币种精度联调，不要原样搬单位 |
| 签名材料 | YOP 私钥 | RSA 签名私钥 ≠ Body `secretKey` |

环境：沙箱 `https://sandbox.kun.global`，生产 `https://openapi.kun.global`。

## 2. 覆盖：缺口与新增

### 2.1 不能当等价替换

| 旧 | 新 | 状态 | 对接含义 |
|----|----|------|----------|
| GET `/rest/v1.0/vcc/user-info` | POST `.../caas/account/query-organization-balance` | partial | 只返回机构余额，不是商户多钱包一包返回。手续费走下方 new_only |
| GET `/rest/v1.0/vcc/clear-record` | 无 | gap | 无商务清算分页。接清算 Webhook，自行落库查询 |
| POST `/rest/v1.0/vcc/card-swap` | 无同名公开接口 | gap | 不要自造 path。依赖换卡时先向平台确认是否开放 |
| 旧 Webhook 报文 | 见 [`Webhook对接.md`](../../产品能力/Webhook/Webhook对接.md) | partial | 事件名和字段不能按旧报文原样解析，验签也要重做 |

### 2.2 旧客户端没有、新侧可接

| 能力 | 新 path | 状态 |
|------|---------|------|
| 机构手续费明细分页 | POST `/rest/v2.0/caas/account/page-query-organization-fee-detail` | new_only |
| 共享账户转入查单 | POST `/rest/v2.0/api/common/userAccount/accountTransferInQuery` | new_only |
| 共享账户转出查单 | POST `/rest/v2.0/api/common/userAccount/accountTransferOutQuery` | new_only |
| 卡充值明细分页 | POST `/rest/v2.0/api/cardManagement/pageQueryCardRechargeDetail` | new_only |
| 卡产品约束 | `cardBins` 出参 | 见 §3.1。无独立卡头分类接口，分类在 `cardBinCategory` |

消费卡整套（KYC、实体卡、PIN、挂失、预售卡、包装地址）属于 **CAAS 迁移**，不在本文件。新接口行为见 [`消费卡对接.md`](../../产品能力/消费卡/消费卡对接.md)；旧 path 对照见 [`../caas/迁移总览.md`](../caas/迁移总览.md)。

若存量客户端调用过「解除封锁码」：公开接口是消费卡 `POST /rest/v2.0/caas/card/remove-block-code`，字段为 `blockCode`（不再用 `removeBlockCode`）。商务卡是否放行以沙箱为准。

## 3. 同能力字段差异

### 3.1 卡产品 `card-bins` → `cardBins`

| | 旧 | 新 |
|--|----|----|
| 入参 | 商户上下文 | `requestNo` + `secretKey` |
| 开卡主键 | bin id | `cardProductCode`（开卡必传，且须来自本次 `cardBins`） |
| 约束 | 旧限额、开卡数量 | `supportedCardModes`、`cardScene`（`COMMERCIAL` / `CONSUMER`）、`supportedCardTypes`、`supportThirdPartyAuth`、充值/转出最小最大额、`transferOutReserveAmount` |
| 分类 | — | 无独立分类接口；用出参 `cardBinCategory` |

开卡前用 `supportedCardModes` / `supportedCardTypes` / `cardScene` 校验，不要只缓存一个 bin id。

### 3.2 开卡 `card-open` → `openCard`

| | 旧 | 新 |
|--|----|----|
| 产品 | `cardBinId` | `cardProductCode` |
| 持卡人 | `cardholderId` | Body `customerId`（持卡人 ID）。没有 `cardholderId` |
| 账户 | 传 `sharedAccountNo` 即共享 | `accountMode` `1`/`2`；`2` 时按产品规则传 `accountNo` |
| 首充 | `amount` / `cardAmount` + `currency` | 开卡体不带充值额。成功后再调 `cardRecharge` |
| 限额 | 扁平四字段 | `limitConfigs[]`，每项带 `transactionType`，金额字段见 §3.6 |
| MCC | `mccRuleType` / `mccList` | `mccConfig.{mccRuleType,mccList,ruleStatus}` |
| 卡类型 | 整数（普通/共享） | `cardType=V/P`。共享只看 `accountMode` |
| 实体卡 | — | `mailing*`、`addressId`，以及城市/州附加地址。`P` 时邮寄地址、邮编、国家码、压花名必填 |
| 出参 | 任务号 `taskId`、卡列表 | `cardId`、`orderId`、`cardNo`、`cardActiveStatus`、`cardMode`、`accountNo`；查单看 `openCardStatus` |
| 查结果 | `taskId` | `originalRequestNo` |

### 3.3 卡列表 `user-cards` → `userCards`

| | 旧 | 新 |
|--|----|----|
| 过滤 | `cardNumber`、`accountNo`、`cardId`、`remark`、`status`、整数 `cardType`、`isShare`、部门码、日期、分页 | `status`（`NORMAL`/`FREEZE`/`CANCEL`/`CANCELLING`/`LOCK`）、`accountMode`（1/2）、`cardRemark`（优先）或兼容字段 `remark`、`accountNo`、开卡日期、`current`/`size`（1～200） |
| 出参 | 持卡人对象、限额用量嵌套 | 扁平持卡人摘要 + `perTransLimit` / `dayLimit` / `monthLimit` / `cardLifeCycleLimit`，以及 `dailyAvailableLimit` / `monthlyAvailableLimit` / `lifetimeAvailableLimit` |
| 与下挂卡 | 易和账户下挂卡混用 | `userCards` 按机构分页，`accountNo` 可选。`accountCardInfo` **必填**共享账户号 |

不再用卡号、整数卡类型、`isShare` 过滤。

### 3.4 改备注 `card-remark` → `updateCardRemark`

| 旧 | 新 |
|----|----|
| `cardId` 或 `cardNumber`，字段 `remark` | 必填 `cardId`。字段 `cardRemark`（覆盖写；空串或纯空白清空为 null）。可选 `customerId` 校验归属 |
| 出参布尔 | `data.cardId` + `data.cardRemark` |

### 3.5 卡信息 / 三要素 / 余额

| | 旧 | 新 |
|--|----|----|
| 入参 | `cardId` 或 `cardNumber` | `cardId` + 持卡人 `customerId` + `ip` + `secretKey` |
| 基本信息 | 一个 `card-info` | `cardBasicInfoQuery`：状态、余额、`limitInfos`、`mccConfig` |
| 三要素 | 独立 `card-key-info`，通道加密 CVV/有效期 | `cardInfoQuery`。日志脱敏 |
| 余额 | `balance` | `availableAmount` / `totalBalanceAmount` / `frozenAmount` + `currencyCode` |

### 3.6 限额 `card-limit` → `cardLimitSettingV2`

| 旧 `limitConfig` | 新 `limitConfigs[]`（另有 `transactionType`） |
|------------------|-----------------------------------------------|
| `perTransLimit` | `singleTransactionLimitAmount` |
| `dayLimit` | `dailyLimitAmount` |
| `monthLimit` | `monthlyLimitAmount` |
| `cardLifeCycleLimit` | `totalLimitAmount` |

### 3.7 充值 / 卡转出

| | 旧 | 新 |
|--|----|----|
| 金额 | `amount` | `rechargeAmount` / `transferOutAmount` |
| 币种 | v1 `currency`；v2 充值 `deductCurrency` | 充值：`rechargeCurrencyCode` + `deductCurrency`。转出：`depositCurrency` |
| 查单 | 一个 `card-recharge-query`（`orderId`）兼充值和转出 | 拆成 `cardRechargeStatusQuery` 与 `cardTransferOutStatusQuery`，键为 `originalRequestNo` |
| 状态 | `status`（整数）+ `balance` | `rechargeStatus` = `PENDING` / `SUCCESS` / `FAILED` 等 |

充值、转出门槛读 `cardBins` 的最小/最大额和 `transferOutReserveAmount`。

### 3.8 冻结、销卡、MCC、持卡人、共享账户、交易与文件

| 能力 | 旧 | 新 |
|------|----|----|
| 冻结 / 解冻 | `card-freeze`、`card-unfreeze` 两个接口 | 同一接口 `cardFreezeAndUnFreezes`，`operationType=FREEZE_CARD` 或 `UNFREEZE_CARD` |
| 销卡 | 入参 `refundCurrency`，出参含退款明细 | 入参无退款币种（`cardId` + 持卡人 `customerId` + `ip`）。出参以订单状态为主 |
| MCC 修改 | `ruleType` / `status` / `mccList` | `mccRuleType` / `ruleStatus` / `mccList` |
| MCC 查询 | 独立 `card-mcc-rule` | 无独立查询。读 `cardBasicInfoQuery` 的 `mccConfig` |
| 持卡人修改 | 持卡人内部 id | 持卡人 `customerId`；出参带回 `customerId` |
| 共享账户 | 字段大体同名 | 建户/改户的 `accountMode` 是 `COMMERCIAL` 或 `CONSUMER`（默认 `COMMERCIAL`）。这与开卡的 `accountMode` 1/2 **不是同一套枚举**。转入、转出各有独立查单。账户查询另有 `customerAccountInfo` |
| 交易查询 | 筛选项更多；`current`/`size` | 筛选项更少；`pageNum`/`pageSize`；路径在 caas |
| 对账文件 | `fileType` + `date` | `fileType` + `fileDate` |
| Webhook 密钥 | 修改配置 | `webhook-sign-key-config`，配置体以 `signKey` 为主 |

## 4. 迁移时按此检查

1. Body `customerId` 改成持卡人 ID；机构号进 Header `Customer-No`。  
2. 卡操作去掉 `cardNumber`，只留 `cardId`。  
3. `cardBinId` 改为 `cardProductCode`，并用 `cardBins` 的模式、形态、场景做校验。  
4. 旧整数 `cardType` 拆成 `accountMode`（1/2）+ `cardType`（V/P）。共享账户接口不要误用 1/2。  
5. 开卡不再带首充；限额改成带 `transactionType` 的数组。  
6. 保存每次写操作的 `requestNo`，用 `originalRequestNo` 查单。充值与转出查单分开。  
7. 金额按新产品精度重接，不要把旧的十进制原样写入整数字段。  
8. `user-info`、清算分页、一键换卡、旧 Webhook 报文单独出方案，不能当 path 替换。
