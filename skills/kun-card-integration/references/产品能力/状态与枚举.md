# 状态与枚举（对接用）

> 下文均为**接口响应 / Webhook 中商户侧应处理的取值**。联调以实际返回与 [opendocs](https://opendocs.kun.global/) 为准；本地字段对照见 `openapi/卡中心.openapi.json`。

---

## 1. 操作结果（开卡 / 销卡 / 充值 / 转出等查询）

多数写操作查询接口返回：

| value | 含义 | 商户处理建议 |
|-------|------|--------------|
| SUCCESS | 成功 | 更新本地终态 |
| FAIL | 失败 | 可换新 requestNo 重试或人工处理 |
| PENDING | 处理中 | 继续轮询或等通知，勿重复写 |

共享账户充值/转出类查询常见为：

| value | 含义 |
|-------|------|
| SUCCESS | 成功 |
| FAIL | 失败 |
| PROCESSING | 处理中（等同于「未终态」，继续查） |

批量开卡/销卡任务头：

| value | 含义 |
|-------|------|
| PENDING | 待执行 |
| PROCESSING | 执行中 |
| SUCCESS | 全部成功 |
| PART_SUCCESS | 部分成功 |
| FAIL | 全部失败 |

## 2. 卡片状态

### 2.1 卡状态（查询）

| value | 含义 | 说明 |
|-------|------|------|
| NORMAL | 正常 | 可交易（还须看激活态等） |
| FREEZE | 冻结 | |
| CANCEL | 已注销 | 不可再做资金/配置类操作 |
| CANCELLING | 销卡中 | 勿再发起充值等 |
| LOCK | 锁定 | 查询时若存在封锁码，可能展示为锁定 |

### 2.2 激活状态

| value | 含义 |
|-------|------|
| ACTIVATED | 已激活 |
| UNACTIVATED | 未激活 |

### 2.3 卡状态变更 Webhook 事件

`webhookType` = `CARD_STATUS_UPDATE_NOTIFY` 时，状态事件常见值：

| value | 含义 |
|-------|------|
| ACTIVE | 激活 |
| FREEZE | 冻结 |
| UNFREEZE | 解冻 |
| CANCEL | 注销 |
| LOCK | 锁定 |
| UNLOCK | 解锁 |
| PHYSICAL_CARD_ACTIVE | 实体卡激活 |

### 2.4 封锁码

| value | 含义 |
|-------|------|
| B0001 | 数字货币质押风险 |
| B0002 | 失败率过高 |
| B0003 | 负金额锁定 |
| B0004 | CVV2 多次失败 |

## 3. 账户模式与卡类型（开卡入参）

### 3.1 accountMode（部分消费卡接口字段名为 cardMode，语义相同）

| value | 含义 |
|-------|------|
| 1 | 预充值（每卡独立余额） |
| 2 | 共享账户（多卡共池） |

须落在已开通产品支持的模式列表；未传时按产品默认（通常优先 1）。

### 3.2 cardType

| value | 含义 | 默认 |
|-------|------|------|
| V | 虚拟卡 | 未传时默认 V |
| P | 实体卡 | 须产品支持 |

### 3.3 产品场景（由卡产品决定，开卡一般不传）

| value | 含义 |
|-------|------|
| COMMERCIAL | 商务卡 |
| CONSUMER | 消费卡 |

### 3.4 共享账户状态

| value | 含义 |
|-------|------|
| VALID | 可用 |
| INVALID | 无效 |
| DELETED | 已删除 |

## 4. KYC

### 4.1 认证申请结果（常见数字码）

| value | 含义 |
|-------|------|
| 0 | 认证中 |
| 1 | 认证成功 |
| 2 | 认证失败 |

### 4.2 案件状态

| value | 含义 |
|-------|------|
| NONE | 无需审核 |
| PENDING | 待审核 |
| APPROVED | 通过 |
| REJECTED | 拒绝 |
| SUPPLEMENT | 待补充 |

### 4.3 KYC 等级

`NONE` / `LEVEL_0` / `LEVEL_1` / `LEVEL_2` / `LEVEL_3`

### 4.4 案件类型（传下列字符串）

| value | 含义 |
|-------|------|
| PRE_CARD_APPLICATION | 申卡前置报送 |
| KYC_REPORT | KYC 报送 |
| UPGRADE_KYC | KYC 升级 |
| MODIFY_INFO | 资料修改 |

### 4.5 AML 结果入参（与案件状态不是同一套值）

| value | 含义 |
|-------|------|
| Approve | 通过 |
| Reject | 拒绝 |

若机构开通「商户侧传入 AML 结果」，则条件必填且通常须为 `Approve`。

### 4.6 证件类型

| value | 含义 |
|-------|------|
| id_card | 身份证 |
| passport | 护照 |
| other | 其他 |

### 4.7 性别

`1` 男 / `2` 女

## 5. 交易 / 授权 / Webhook

### 5.1 交易状态（查询）

| value | 含义 |
|-------|------|
| PENDING | 处理中 |
| SUCCESS | 成功 |
| FAILED | 失败（注意拼写是 **FAILED**） |

### 5.2 对外交易类型（查询 / 通知常用）

| value | 含义 |
|-------|------|
| AUTHORIZATION | 授权（含消费、预授权等） |
| CASH_ADVANCE | 取现 |
| REFUND | 退货 |
| TRANSFER_OUT | 汇款 |
| TRANSFER_IN | 收款 |
| VOID | 撤销 |

### 5.3 授权决策 Webhook 响应

商户同步返回：

| authResult | 含义 |
|------------|------|
| A | 批准 |
| D | 拒绝 |

建议同时回传 `requestNo`、`code`/`message`；拒绝时可填 `responseCode`、`declinedReason`。

### 5.4 webhookType（平台推送类型）

| value | 含义 |
|-------|------|
| AUTH_WEBHOOK | 交易授权（需同步返回 A/D） |
| AUTH_RESULT_NOTIFY | 授权结果通知 |
| CLEARING_RESULT_NOTIFY | 清算结果 |
| RELEASE_RESULT_NOTIFY | 授权释放 |
| 3DS_OTP_WEBHOOK | 3DS OTP |
| PIN_SETUP_NOTIFY | PIN 设置成功 |
| CARD_STATUS_UPDATE_NOTIFY | 卡状态变更 |
| CARD_TOKEN_NOTIFY | Card Token 状态 |
| ADD_CARD_BLOCK_CODE_NOTIFY | 封锁码新增 |
| PRESALE_CARD_APPLY_RESULT_NOTIFY | 预售卡申请结果 |
| KYC_RESULT | KYC 审核结果 |
| KYC_SUBMIT_COMPLETE | SDK-KYC 提交完成 |
| WALLET_RECHARGE_RESULT_NOTIFY | 钱包充值结果 |
| WALLET_RECHARGE_RISK_EXCEPTION_NOTIFY | 钱包充值风控异常 |
