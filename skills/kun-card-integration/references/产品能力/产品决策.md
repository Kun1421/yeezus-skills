# 产品决策（商务卡 / 消费卡 / Webhook）

本文档解决「**选哪条卡链路**」；选定后「**怎么接**」见：

- `商务卡/商务卡对接.md`
- `消费卡/消费卡对接.md`
- `Webhook/Webhook对接.md`

---

## 一、先分清两条卡产品

| 维度 | 商务卡（Commercial） | 消费卡（Consumer / CaaS） |
|------|----------------------|---------------------------|
| 典型客户 | 企业差旅、广告投放、SaaS 发卡、批量虚拟卡 | C 端用户发卡、需要实名 KYC、实体卡邮寄 |
| 路径前缀 | `/rest/v2.0/api/**` | `/rest/v2.0/caas/**` |
| 持卡人 | 轻量「添加持卡人」即可拿到 `customerId` | 必须先 KYC（报送 / SDK）通过后再开卡 |
| 卡形态 | 虚拟卡为主（`cardType=V`） | 虚拟卡 + 实体卡 + 预售卡 |
| 账户模式 | 预付卡（`accountMode=1`）或共享账户（`accountMode=2`） | 以卡余额/充值为主，另有实体卡激活、PIN、封锁码等 |
| 开卡主接口 | `POST /rest/v2.0/api/common/openCard`（及批量） | `POST /rest/v2.0/caas/card/apply-card`（及预售/实体卡系列） |

> **不要混用前缀**：商务卡流程不要调 `/caas/card/apply-card`；消费卡流程不要用商务卡持卡人接口代替 KYC。

## 二、决策树

```text
商户要接什么？
├─ 只收平台推送（授权/清算/OTP/卡状态…）──► Webhook/Webhook对接.md
│     （通常与商务卡或消费卡主流程一起接）
├─ 给企业员工 / 投放账户批量发虚拟卡、可共享余额
│     └─► 商务卡/商务卡对接.md
│           ├─ 单人额度独立 ──► 预付卡 accountMode=1 + 卡充值/转出
│           └─ 多卡共用资金池 ──► 先建共享账户 accountMode=2 + 账户充值
└─ 给 C 端个人发消费卡（要实名、可能实体卡）
      └─► 消费卡/消费卡对接.md
            ├─ 仅虚拟卡 ──► KYC → apply-card(V) → 激活/充值
            ├─ 实体卡邮寄 ──► KYC → apply-card(P)/apply-physical-card → 激活验证码
            └─ 预售卡 ──► presale-card-apply → 结果通知/查询 → 激活
```

## 三、场景关键词匹配

### 商务卡

| 场景 | 关键词 |
|------|--------|
| 持卡人 | 商务卡持卡人、添加持卡人、commercial cardholder |
| 开卡 | 开卡 V2、openCard、批量开卡、batchOpenCard、虚拟卡批量 |
| 卡操作 | 冻结解冻、销卡、限额、MCC、卡信息/CVV、激活 |
| 资金 | 预付卡充值、卡转出、充值记录 |
| 共享账户 | 共享账户、SVA、accountTransferIn/Out、账户下挂卡 |
| 机构账户 | 机构余额、手续费明细 |

### 消费卡

| 场景 | 关键词 |
|------|--------|
| KYC | KYC 报送、kyc-submit、KYC SDK、inital-kyc-url、KYC 结果 |
| 开卡 | apply-card、开卡状态、实体卡、预售卡、补卡、挂失 |
| 卡生命周期 | 激活、冻结、销卡、PIN 设置 URL、封锁码、限额、MCC |
| 资金/交易 | 卡充值、余额、交易分页查询 |
| 配置/文件 | 包装地址、webhook 签名密钥、对账文件、Base64 上传 |

### Webhook

| 场景 | 关键词 |
|------|--------|
| 授权决策 | transaction webhook、授权批准/拒绝、auth decision |
| 资金结果 | clearing、清算通知、交易结果通知 |
| 安全 | 3DS OTP、otp-3ds、PIN 设置结果 |
| 卡事件 | 卡状态变更、Token 通知、封锁码、预售卡申请结果、授权释放 |
| KYC 通知 | kyc-notify、kyc-completion-notify |

## 四、标准澄清模板

### 模板 1：仅说「要对接卡」

请商户回答：

1. 发卡对象是**企业员工/广告账户**，还是**C 端个人消费者**？
2. 是否需要**实名 KYC** 或**实体卡邮寄**？
3. 资金是**每张卡独立充值**，还是**多卡共享一个账户余额**？
4. 是否需要接收**交易授权实时决策**或**清算/OTP** 等推送？

### 模板 2：商务卡细节

1. 预付卡还是共享账户？
2. 单张开卡还是批量？预估批量规模？
3. 是否需要卡级限额 / MCC 限制？
4. Webhook 是否已有接收地址？

### 模板 3：消费卡细节

1. KYC 用 API 报送还是 SDK URL？
2. 虚拟卡 / 实体卡 / 预售卡？
3. 是否需要 PIN、3DS OTP、挂失补卡？
4. 开卡后资金从哪来（充值接口）？

### 模板 4：超出范围

本技能覆盖 KUN **卡开放 API**（商务卡 / 消费卡 / 卡 Webhook）。若需求是法币充值、提现、换汇等其他产品，引导 [opendocs.kun.global](https://opendocs.kun.global/) 对应文档，**不臆造卡接口**。

## 五、与 Webhook 的关系

- **商务卡 / 消费卡主流程**：商户**主动调用**开放 API。
- **Webhook**：平台**主动调用**商户 URL（授权决策为同步返回批准/拒绝；其余多为异步通知）。
- 绝大多数生产接入 = **主流程 API + Webhook**；仅查单、不对交易决策的商户可暂缓授权类 webhook，但仍建议接清算/卡状态。
