# 消费卡对接

面向 **C 端消费卡**：KYC → 开卡（虚拟/实体/预售）→ 激活/PIN/限额 → 充值与交易查询；卡事件与授权配合 `../Webhook/Webhook对接.md`。

> 对接必读：[`字段要求.md`](../字段要求.md)、[`状态与枚举.md`](../状态与枚举.md)。索引：`consumer-*`。

## 业务主流程

### A. API 报送 KYC + 虚拟卡

```text
① base64upload 上传证件 → fileId
② kyc-submit（customerId 商户侧唯一，kycLevel 按产品）
③ 等待 kyc-notify / 或 kyc-result-inquiry 至通过
④ apply-card（cardType=V，KYC 通过后的 customerId）
⑤ query-apply-card-status
⑥ （可选）activation / limit-config / mcc-setting
⑦ recharge → recharge-status-query
⑧ 用卡；接 Webhook（授权/清算/OTP/卡状态）
```

### B. KYC SDK

```text
inital-kyc-url → 前端打开 SDK
→ kyc-completion-notify（提交完成）
→ kyc-notify（审核结果）
→ 再 apply-card
```

### C. 实体卡

```text
KYC 通过 → apply-card(P) 或 apply-physical-card
→ 补齐邮寄地址 / addressId（包装地址）
→ 收卡后 send-activate-verify-code → verify-physical-card-active / activation
→ get-pin-setup-url（如需）→ pin-setup webhook
```

### D. 预售卡

```text
presale-card-apply
→ presale-card-apply-result webhook 或 query-presale-apply-result
→ presale-card-activation
```

## 接入步骤

1. 平台密钥与签名（同商务卡）；配置 `webhook-sign-key-config`。
2. 明确 KYC 等级与影像要求；先文件上传再报送。
3. **仅 KYC 通过后开卡**；`apply-card` 描述要求 KYC 通过。
4. 实体卡：提前维护包装地址；邮寄字段与 `cardType=P` 条件必填以 OpenAPI 为准。
5. 终态：开卡/充值以查询接口 + webhook 为准，不以前端成功页为准。
6. 交易对账：`recon-file-download` + `query-transaction`。

## 状态与异常（本场景）

| 阶段 | 成功条件 | 失败 / 处理中 |
|------|----------|----------------|
| KYC | 案件 APPROVED 或申请态成功 | PENDING/SUPPLEMENT 等待；REJECTED/失败则补件或新单 |
| 开卡 | 查询/通知至成功 | PENDING 查 `query-apply-card-status`（按文档字段）；FAIL 新 requestNo |
| 充值 | 充值状态 SUCCESS | PENDING 查 `recharge-status-query`；超时只查 |
| 卡状态 | NORMAL+已激活等 | FREEZE/LOCK/CANCELLING 限制操作 |

**未 KYC 通过禁止开卡。** 超时/5xx → 未知 → 只查单。详见 [`状态判断与异常处理.md`](../状态判断与异常处理.md)。

## 易错点

- **未 KYC 开卡**：须案件通过后再 `apply-card`；商务卡持卡人接口**不能**替代 KYC。
- **KYC 状态**：申请态 `0/1/2`；案件态 `NONE/PENDING/APPROVED/REJECTED/SUPPLEMENT`；`caseType` 传 `KYC_REPORT` 等 **value**（非枚举名）。
- **Level1 必填**：姓名、证件、生日、性别、有效期、国籍、countryNo（三位数字）、证件正面/人脸 fileId、邮箱、居住地国家/州/市/详址、postalCode——见 `字段要求.md`。
- **amlResult**：机构开 AML API 时条件必填，取值 `Approve`/`Reject`（不是 APPROVED）。
- **customerId**：全链路同一商户侧 ID（KYC → 开卡 → webhook）。
- **开卡字段**：部分接口用 `cardMode`，与 `accountMode` 同义（默认 1）；若走 KYC SDK 且资料已在平台，姓名/邮箱等可按联调结果省略。
- **实体卡**：`cardType=P` → 邮寄三字段 + 压花名必填。
- **激活态**：`ACTIVATED` / `UNACTIVATED`。
- **敏感解密**：`cardNo` / `cvv` / `expiryDate` 用机构 `sensitiveKey` + AES/CBC；**IV 固定 `"1234567890000000"`**（见 [`字段要求.md`](../字段要求.md) §2.3）。
- **封锁码**：`B0001`～`B0004`；通知类型 `ADD_CARD_BLOCK_CODE_NOTIFY`。
- **路径**：消费卡在 `/rest/v2.0/caas/**`；交易结果通知 path 含历史拼写 `result-nofity`，按文档原样对接。

## 排障

- KYC 长期处理中 → 查 `kyc-result-inquiry` + 是否收到 `kyc-notify`
- 开卡失败 → KYC 状态、产品码、实体卡邮寄字段
- OTP 未达用户 → `otp-3ds` webhook 是否到达商户、商户是否转发
- 详见 `../../troubleshooting.md`
