# 字段要求（对接用）

> 目标：帮商户一次填对参数。权威字段定义以本地 `openapi/卡中心.openapi.json` 与 [opendocs](https://opendocs.kun.global/) 为准；下列补充**条件必填与易错约束**。  
> 公共业务字段：几乎所有接口 body 需 `requestNo`（商户侧唯一，幂等）+ `secretKey`（机构密钥，≠ RSA 签名私钥）。`organizationNo` 一般由开放平台按应用映射，**文档未要求时不要自行编造**。

符号：`*` 必填 · `△` 条件必填 · `○` 可选

---

## 2.1 商务卡 — 机构下分页查卡（旧 user-cards）

`POST /rest/v2.0/api/common/userCards`  
权威字段：`references/openapi/userCards.openapi.json`

| 字段 | 约束 | 说明 |
|------|------|------|
| requestNo * / secretKey * | | |
| current * / size * | current≥1；size 1~200（超 200 截断） | 分页 |
| status ○ | `NORMAL`/`FREEZE`/`CANCEL`/`CANCELLING`/`LOCK` | 非法 → `KLC0003` |
| accountMode ○ | `1` 预充值 / `2` 共享 | 同开卡；非法 → `KLC0003` |
| cardRemark ○ / remark ○ | | 备注模糊匹配；`cardRemark` 优先，否则用 `remark` |
| accountNo ○ | | 精确匹配账户下卡；**非必填**（对比 `accountCardInfo`） |
| startDate / endDate ○ | `yyyy-MM-dd` | 开卡时间范围 |

与 `accountCardInfo`：本接口按**机构**分页；后者**必填**共享账户号。

示例 JSON：

```json
{
  "requestNo": "req_cards_001",
  "secretKey": "YOUR_SECRET_KEY",
  "status": "NORMAL",
  "accountMode": 1,
  "current": 1,
  "size": 20
}
```

## 2.2 商务卡 — 修改卡备注（旧 card-remark）

`POST /rest/v2.0/api/common/updateCardRemark`  
权威字段：`references/openapi/updateCardRemark.openapi.json`

| 字段 | 约束 | 说明 |
|------|------|------|
| requestNo * / secretKey * / cardId * | | |
| customerId ○ | | 建议传；与卡归属一并校验 |
| cardRemark ○ | ≤255 | **覆盖写**；空串/仅空白 trim 后清空为 null；超长 → `KLC0003` |

旧 VCC 字段名 `remark` → 新侧统一用 **`cardRemark`**。开卡时亦可带 `cardRemark`（见 §2）。

示例 JSON：

```json
{
  "requestNo": "req_remark_001",
  "secretKey": "YOUR_SECRET_KEY",
  "cardId": "YOUR_CARD_ID",
  "customerId": "YOUR_CUSTOMER_ID",
  "cardRemark": "marketing campaign"
}
```

常见码：`0000` 成功；`KLC0002` 缺参；`KLC0003` 非法；`KLU0006` 卡不存在/跨机构。见 [`异常码处理.md`](异常码处理.md)。

## 3. 消费卡 — 申请开卡

`POST /rest/v2.0/caas/card/apply-card`

| 字段 | 约束 | 说明 |

须 **KYC 通过后再开卡**。

## 5. Webhook — 交易授权

平台调用商户地址；商户**同步**返回是否批准。

### 5.1 请求（平台 → 商户）关键字段

| 字段 | 说明 |
|------|------|
| webhookType | 授权类多为 `AUTH_WEBHOOK` |
| requestNo / transactionId / cardId / customerId | |
| transactionType / transactionCurrency / transactionAmount | |
| transactionDirection | `C` 贷记 / `D` 借记 |
| merchantType | MCC |
| acquireMerchantName / City / CountryCode | |
| transmissionDateTime | `YYYYMMDDHHmmSS` |
| tokenFlag / dpan / walletProvider | Token 交易时 |
| firstTransactionId 等 | 增量授权关联时 |

### 5.2 响应（商户 → 平台）

| 字段 | 要求 |
|------|------|
| authResult * | **`A`** 批准 / **`D`** 拒绝 |
| requestNo | 建议回传 |
| code / message | 建议回传 |
| responseCode / declinedReason | 拒绝时建议填 |

须低延迟、幂等（同一 `transactionId` 返回一致结果）。超时策略以商务/联调约定为准。

## 6. 条件必填速查

| 场景 | 条件 | 必填 |
|------|------|------|
| 实体卡 | cardType=`P` | 邮寄地址 + 邮编 + 邮寄国家数字码 + 压花名 |
| 共享账户开卡 | accountMode=`2` | 产品须支持；可传 accountNo |
| 有手机号 | mobilePhone 有值 | mobilePhoneArea |
| KYC | 报送 | Level1 上表字段 |
| 商务开卡 | — | customerId = 持卡人接口返回值 |
| 消费开卡 | — | KYC 通过后的同一 customerId |
