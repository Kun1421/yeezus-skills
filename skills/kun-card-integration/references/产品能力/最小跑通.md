# 最小跑通（几分钟出可运行调用）

目标：锁定场景后，Agent **一次给出**「步骤 + 必填 JSON + 签名调用命令/代码」，商户填入沙箱凭证即可试跑。

跑通之后，必须继续按 [`状态判断与异常处理.md`](状态判断与异常处理.md) 与 [`examples/`](../../examples/) 补齐**可落地方案**（判态、查单、异常、幂等），不能停在「发出 HTTP 请求」。

> 凭证占位符一律用 `YOUR_*`；**禁止**在聊天中索要或回显真实私钥内容。  
> 跑脚本前：`pip install -r scripts/requirements.txt`

---

## 跑通前 60 秒确认

向商户确认（一次问完，≤5 项）：

1. 场景：`商务卡预付虚拟卡` / `商务卡共享账户` / `消费卡 KYC+虚拟卡` / `仅 Webhook 授权` 之一  
2. 环境：沙箱 / 生产（生产须二次确认）  
3. 语言（与 **yop-demo** 对齐）：`Python` / `Java` / `Java-Web` / `Node.js` / `TypeScript` / `Go` / `PHP` / `.NET`（详见 [`多语言对齐.md`](多语言对齐.md)）  
4. 是否已有：`App-Key`、`Customer-No`、RSA 私钥文件路径、`secretKey`、（可选）`cardProductCode`  
5. 是否需要一起接 Webhook（授权 `A`/`D`）

未给 `cardProductCode` 时：先跑 **步骤 0 拉产品列表**。

---

## 黄金路径 A：商务卡 · 预付虚拟卡（最短）

```text
0 cardBins → 1 添加持卡人 → 2 openCard(V, accountMode=1) → 3（可选）openCardQuery → 4（可选）充值
```

### 步骤 0 — 卡产品列表

`POST /rest/v2.0/api/common/cardBins`

```json
{
  "requestNo": "req_bins_001",
  "secretKey": "YOUR_SECRET_KEY",
  "ip": "127.0.0.1"
}
```

从返回 `data[]` 取 `cardScene=COMMERCIAL` 且 `supportedCardTypes` 含 `V` 的 `cardProductCode`；记下 `supportedCardModes`。

### 步骤 1 — 添加持卡人

`POST /rest/v2.0/caas/customer/commercial/add-cardholder`

```json
{
  "requestNo": "req_ch_001",
  "secretKey": "YOUR_SECRET_KEY",
  "firstName": "San",
  "lastName": "Zhang",
  "email": "demo.holder@example.com"
}
```

保存响应 `data.customerId`。

### 步骤 2 — 开卡

`POST /rest/v2.0/api/common/openCard`

```json
{
  "requestNo": "req_open_001",
  "secretKey": "YOUR_SECRET_KEY",
  "ip": "127.0.0.1",
  "customerId": "YOUR_CUSTOMER_ID_FROM_STEP1",
  "cardProductCode": "YOUR_CARD_PRODUCT_CODE",
  "cardType": "V",
  "accountMode": 1
}
```

看 `data.openCardStatus`：

| openCardStatus | 动作 |
|----------------|------|
| SUCCESS | 本地终态成功 |
| FAIL | 本地失败；修参后**新** requestNo |
| PENDING | 用 `openCardQuery`（`originalRequestNo`=开卡 requestNo）轮询；**禁止再开一笔** |

超时/无响应：视为未知 → 只查单。详见 `状态判断与异常处理.md`。

### 一键调用（沙箱）

```bash
cd skills/kun-card-integration/scripts
python kun_client.py call \
  --env sandbox \
  --app-key YOUR_APP_KEY \
  --customer-no YOUR_CUSTOMER_NO \
  --private-key ./keys/merchant_private.pem \
  --path /rest/v2.0/api/common/cardBins \
  --body '{"requestNo":"req_bins_001","secretKey":"YOUR_SECRET_KEY","ip":"127.0.0.1"}'
```

## 黄金路径 B：商务卡 · 共享账户

```text
0 cardBins → 1 创建共享账户 → 2 账户充值(+查询) → 3 添加持卡人 → 4 openCard(V, accountMode=2, accountNo)
```

开卡 body 相对路径 A 增加：

```json
"accountMode": 2,
"accountNo": "YOUR_SHARE_ACCOUNT_NO"
```

账户接口见 `商务卡/商务卡对接.md`（`userAccount/create`、`accountTransferIn`）。

---

## 黄金路径 C：消费卡 · KYC + 虚拟卡

```text
0 上传证件 → 1 kyc-submit → 2 等 KYC_RESULT / 查询通过 → 3 apply-card(V) → 4 状态查询 → 5（可选）充值
```

- Level1 必填见 `字段要求.md` §4  
- `customerId` 全流程同一商户侧 ID  
- 开卡 path：`/rest/v2.0/caas/card/apply-card`

---

## 黄金路径 D：授权 Webhook（可与 A/C 并行）

1. 配置 `webhook-sign-key-config`  
2. 实现接收：验签 → 幂等 → 若 `AUTH_WEBHOOK` 则 JSON 返回 `{"authResult":"A"}` 或 `"D"`  
3. 样例见 `Webhook/Webhook对接.md`

---

## Agent 代码输出必须包含

### A. 沙箱可跑通

1. 环境与网关 URL  
2. 签名头 + 规则引用  
3. 有序接口 + 完整 JSON（占位符）  
4. `kun_client.py call ...` 或等价命令  

### B. 可落地（与 A 同时交付）

1. 以 `examples/commercial_prepaid_flow.py` 为骨架的状态分支  
2. `SUCCESS` / `FAIL` / `PENDING` / 超时未知 的处理  
3. 查单方法（开卡：`originalRequestNo`）  
4. 异常分类：鉴权不可重试写 / 明确 FAIL 换新单 / 未知只查  
5. Webhook 若需要：`authResult=A|D` + 幂等  
6. 上生产清单：DB 唯一 requestNo、定时补偿、响应验签、日志脱敏  

语言与 yop-demo 对齐；**任意语言**保持相同判态与异常结构。联调可先用 `kun_client.py`，业务代码按客户语言交付。
