# 多语言对齐（与 yop-demo 同级）

对接 skill **不绑定单一语言**。语言矩阵与旧 VCC 示例仓 **yop-demo** 对齐，便于存量客户迁移与多栈研发选用。

> 权威行为（判态 / 查单 / 异常）与语言无关，见 [`状态判断与异常处理.md`](状态判断与异常处理.md)。  
> 仓库内已落盘样例见 [`examples/README.md`](../../examples/README.md)；未落盘语言由 Agent **按同构模板即时生成**。

---

## 1. 支持语言（对齐 yop-demo）

| 语言 ID（对话可用） | 对齐 yop-demo 目录 | 新开放 API 样例状态 | Agent 默认产出 |
|--------------------|--------------------|---------------------|----------------|
| `python` | `python-demo` | 仓库已有：`examples/commercial_prepaid_flow.py` + `scripts/kun_client.py` | 优先复用仓库样例 |
| `java` | `java-demo` / `java-demo-without-sdk` | 仓库已有：`examples/java/` | 优先复用仓库样例 |
| `java-web` | `java-web-demo` | 按需生成（Spring 等 Web 封装） | 同构判态 + Controller/Service 骨架 |
| `nodejs` / `javascript` | `nodejs-demo` | 按需生成 | Node 签名客户端 + 开卡流程 |
| `typescript` | `typescript-demo` | 按需生成 | TS 签名客户端 + 开卡流程 |
| `go` | `go-demo` | 按需生成 | Go HTTP + RSA 签名 |
| `php` | `php-demo` | 按需生成 | PHP 签名 + 流程 |
| `dotnet` / `csharp` | `dotNet-demo` | 按需生成 | .NET 签名 + 流程 |

未点名语言时：先问一次；若客户要「最快跑通」，推荐 **Python 联调脚本**（`kun_client.py`），业务代码仍按其工程语言生成。

## 2. 生成纪律（任意语言必须相同）

无论输出哪种语言，落地代码须包含：

1. RSA SHA256withRSA 请求签名（头：`App-Key` / `Api-Version` / `Customer-No` / `Timestamp` / `Sign`）  
2. Body：`secretKey` + 唯一 `requestNo`  
3. 平台 `code` 校验 + 业务状态 `SUCCESS` / `FAIL` / `PENDING`  
4. 超时 / 5xx / 无法解析 → `UNKNOWN` → **只查单不重开**  
5. 敏感字段不落明文日志  

禁止：只给 curl、或只换 path 不改判态。

---

## 3. 与 yop-demo 的关系

| | yop-demo（旧 VCC / YOP） | 本 skill（新开放 API） |
|--|-------------------------|------------------------|
| 用途 | 旧网关签名、旧 `/rest/v1.0/vcc/*` 联调 | 新网关 RSA 头签、`/rest/v2.0/...` |
| 语言覆盖 | 上表各 `*-demo` | **同一语言集合**；样例逐步补齐 |
| 迁移 | 客户旧代码多来自 yop-demo 语言栈 | 迁移时按同语言对照改客户端，见后续 `kun-vcc-api-migration` |

面客时：**不要**要求客户先学某一语言；按其现有栈（常与 yop-demo 一致）出代码。
