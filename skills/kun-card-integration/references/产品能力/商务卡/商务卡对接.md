# 商务卡对接

面向**企业/平台批量虚拟卡**：轻量持卡人 → 开卡（单张/批量）→ 限额 MCC → 预付充值或共享账户资金 → 冻结/销卡；交易侧配合 `Webhook对接.md`。

> 对接必读：[`字段要求.md`](../字段要求.md)、[`状态与枚举.md`](../状态与枚举.md)；字段清单见 `../../openapi/卡中心.openapi.json`。索引：`../api-index.yaml` → `commercial-*`。

## 业务主流程

### A. 预付卡（每卡独立余额）

```text
① cardBins 确认产品与 supportedCardTypes/Modes
② commercial/add-cardholder → customerId
③ openCard（accountMode=1, cardType=V, customerId, cardProductCode）
④ openCardQuery 确认成功（异步时）
⑤ （可选）cardLimitSettingV2 / cardMccSetting
⑥ cardRecharge → cardRechargeStatusQuery
⑦ 用卡；接 Webhook（授权/清算等）
⑧ 冻结/解冻 / cancelCard；必要时 cardTransferOut 抽回余额
```

### B. 共享账户（多卡共池）

```text
① cardBins
② userAccount/create → accountNo
③ accountTransferIn 充值共享账户 → accountTransferInQuery
④ add-cardholder → openCard（accountMode=2, 指定 accountNo）
⑤ accountCardInfo / queryTransDetail 运维查询
⑥ 卡侧仍可冻结/销卡；资金优先在账户层转出 accountTransferOut
```

### C. 批量开卡

```text
batchOpenCard → 保存任务号 → 轮询 batchOpenCardTask
（单卡失败不影响整批策略以接口文档/响应为准）
```

## 接入步骤

1. **平台准备**：沙箱/生产 App-Key、Customer-No、RSA 私钥、机构 `secretKey`；配置 IP 白名单（见平台文档）。
2. **签名**：按 `../../平台文档/鉴权认证机制.md` 对 body 顶级字段 + `customerNo` + `timestamp` 加签。
3. **拉产品**：`cardBins`，确认 `cardProductCode`、支持的 `cardType`/`accountMode`。
4. **持卡人**：商务卡走 `commercial/add-cardholder`（**不走消费卡 KYC**）；保存返回的持卡人 ID 作为后续 `customerId`。
5. **开卡**：`openCard`；`requestNo` 商户侧唯一；商务卡 `cardType` 仅虚拟 `V`。
6. **资金**：预付走卡充值；共享先账户充值再开卡挂账。
7. **Webhook**：见 `../Webhook/Webhook对接.md`（授权决策、清算、卡状态等）。
8. **运维查询**：卡信息/余额/充值明细/机构余额；敏感信息接口需合规管控。
9. **敏感字段解密**：`cardInfoQuery` / 开卡出参等返回的 `cardNo`、`cvv`、`expiryDate` 为密文。用机构 **`sensitiveKey`（Base64）** 做 **AES/CBC/PKCS5Padding** 解密；**IV 固定为 `"1234567890000000"`**（UTF-8，16 字节）。明文勿写日志。

## 状态与异常（本场景）

| 操作 | 同步看 | 查询接口 | 关键入参 |
|------|--------|----------|----------|
| 开卡 | `data.openCardStatus` | `/api/common/openCardQuery` | `originalRequestNo`=开卡 requestNo |
| 充值 | 同步状态字段 | `/api/cardManagement/cardRechargeStatusQuery` | `originalRequestNo`+`cardId`+`customerId` |
| 转出 | 同步状态字段 | `cardTransferOutStatusQuery` | 同模式 |
| 批量 | 任务号 | `batchOpenCardTask` | 任务查询至 SUCCESS/PART_SUCCESS/FAIL |
| 共享账户充提 | — | `accountTransferInQuery` / OutQuery | 状态多为 PROCESSING/SUCCESS/FAIL |

规则摘要：`SUCCESS`/`FAIL` 终态；`PENDING`/`PROCESSING` 只查不重开；超时当未知先查。完整矩阵 → [`状态判断与异常处理.md`](../状态判断与异常处理.md)。

落地样例：`examples/commercial_prepaid_flow.py`。

## 易错点

- **路径混用**：商务开卡用 `/api/common/openCard`，不要调 `/caas/card/apply-card`。
- **持卡人来源**：`customerId` = `commercial/add-cardholder` 响应的持卡人 ID（不传 customerId 去添加接口）。
- **accountMode**：`1` 预充值 / `2` 共享；须 ∈ 产品 `supportedCardModes`；未传按产品默认。`2` 时可指定 `accountNo`。
- **cardType**：空默认 `V`；是否允许 `P` 看产品 `supportedCardTypes`（商务产品通常仅 V）。
- **实体卡条件必填**：`P` 时邮寄地址+邮编+邮寄国家数字码+压花名必填。
- **userCards vs accountCardInfo**：`userCards` 机构维度分页（`accountNo` 可选）；`accountCardInfo` **必填**共享账户号。旧 VCC `user-cards` 迁到 `userCards`。
- **updateCardRemark**：字段名是 `cardRemark`（不是旧 `remark`）；覆盖写；空串/空白清空。旧 VCC `card-remark` 迁到本接口。
- **查询状态**：开卡/销卡/充值转出多为 `SUCCESS`/`FAIL`/`PENDING`；共享账户充提多为 `PROCESSING`/`SUCCESS`/`FAIL`；批量任务另有 `PART_SUCCESS`。详见 `状态与枚举.md`。
- **卡状态**：`NORMAL`/`FREEZE`/`CANCEL`/`CANCELLING`；有封锁码时查询可能为 `LOCK`（`userCards` 过滤同此枚举）。
- **幂等**：`requestNo` 唯一；非终态先查再重试。
- **secretKey ≠ RSA 签名私钥**；勿传未文档化字段。
- **敏感查卡**：含 CVV/有效期的接口须权限与日志脱敏。
- **敏感解密**：密钥是 `sensitiveKey`（≠ `secretKey`、≠ RSA 私钥）；算法 AES/CBC/PKCS5Padding；**IV 一律 `"1234567890000000"`**，不要自造或随机 IV。

## 排障

- 签名失败 → `../../troubleshooting.md`「签名验签」
- 开卡失败 → 核对产品码、持卡人、accountMode、cardType；查 `openCardQuery`
- 充值无结果 → `cardRechargeStatusQuery` / 账户侧 `accountTransferInQuery`
- 授权类问题 → `../Webhook/Webhook对接.md`
